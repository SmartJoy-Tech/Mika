# Upstream v0.1.37 build workflow review

Reviewed on 2026-11-06 for the personal TinyFox fork.
Upstream: `wangzan101/Mika@2c4563bcd8bad7b4b4e3c6de39a3e3f19be7ff98`.

## Decision

Accept the new CI workflow with pinned Action commits and checkout credentials
disabled. Keep the existing manual-review gate for future upstream automation
changes. Promotion and phone installation require passing validation.

## Reviewed changes

- `ci.yml` runs core JVM, Python CLI/translation, Android debug, and Go relay
  tests. It requests only `contents: read`, never references signing secrets,
  and has no publish/deploy job, `pull_request_target`, or privileged container.
- Artifact uploads are restricted to test reports on failure with seven-day
  retention. Each job has a bounded timeout. Dependencies and CI actions still
  execute third-party code; this review is not a proof of absence of all risks.
- Replaced all major-version Action tags with the corresponding commits read
  from the official repositories. Disabled persisted checkout credentials.
- Adapted push triggers to the fork's `tinyfox` and `update/**` branches so the
  reviewed workflow can run on the candidate before promotion.
- `.gitattributes` standardizes LF text and CRLF Windows scripts. The upstream
  `gradlew.bat` change has no content difference when ignoring line endings.
- Existing `tinyfox-build.yml` builds and inspects unsigned release APKs; the
  permanent personal signing key stays on the local Windows account.

## Compatibility checks

- Preserve application ID `io.github.smartjoytech.tinyfox`, accessibility entry
  `io.github.smartjoytech.tinyfox.a11y.TinyFoxAccessibilityService`, SmartJoy
  artwork, personal settings, update channel and signing-certificate pin.
- Target version: `0.1.37-tinyfox.1` / code `3801`.
- No new requested Android permissions. The new WeChat service is not exported;
  its channel and the new Root options default to disabled.
- Resolve prompt snapshot conflicts from upstream, regenerate against the
  merged code, and check that only Mika-to-TinyFox identity, corresponding
  lengths and system hashes differ. Tool definitions and scenario outcomes
  remain identical to upstream.
- Five sync safety regression tests passed locally. Release promotion also
  requires the cloud core/app test suites and actual APK identity checks.

Phone update uses the same certificate and package with `adb install -r`.
Existing data is retained; settings and schedules are compared before/after.
No model, proxy, DNS, Root, or WeChat-channel settings are changed by this update.
